# Plan: Tích hợp Oracle Database vào Hệ thống Hotel Booking Microservices (ASP.NET Core)

## 1. Tổng quan
Dự án Hotel Booking xây dựng theo kiến trúc microservices trên ASP.NET Core, lần này lựa chọn **Oracle Database** làm hệ quản trị cơ sở dữ liệu chính thay vì SQL Server. Oracle phù hợp với các hệ thống doanh nghiệp lớn, yêu cầu tính sẵn sàng cao, xử lý giao dịch phức tạp và có đội ngũ quản trị chuyên sâu.

Mỗi microservice sẽ có **database riêng** (Database per Service). Trong Oracle, ta có thể triển khai bằng một trong hai cách:
- **Tạo các Pluggable Database (PDB) riêng biệt** (nếu dùng Oracle Multitenant) – tốt nhất cho isolation.
- **Sử dụng các schema/user riêng** trên cùng một instance (CDB hoặc non-CDB) – tiết kiệm chi phí, phổ biến hơn.

Trong kế hoạch này, ta giả định dùng **schema riêng cho mỗi service** (mỗi schema là một user Oracle với tablespace riêng), vẫn đảm bảo cô lập dữ liệu và phát triển độc lập.

Mục tiêu của kế hoạch:
- Thiết kế cơ sở dữ liệu Oracle cho từng microservice.
- Cấu hình EF Core Oracle provider, quản lý migration.
- Áp dụng các best practice về bảo mật, hiệu năng, vận hành.
- Xây dựng lộ trình triển khai.

## 2. Kiến trúc tổng thể
Các service chính:
- **IdentityService** – Quản lý người dùng, xác thực, phân quyền.
- **HotelService** – Quản lý khách sạn, phòng, tiện nghi, tồn kho phòng.
- **BookingService** – Xử lý đặt phòng, kiểm tra khả dụng, lịch sử đặt.
- **PaymentService** – Xử lý thanh toán, hóa đơn.
- **NotificationService** – Gửi thông báo, quản lý template.

Mỗi service dùng một **Oracle user/schema** riêng để lưu trữ dữ liệu. Việc giao tiếp giữa các service thông qua message broker (RabbitMQ/Azure Service Bus) và REST API, đảm bảo **eventual consistency**.

## 3. Thiết kế cơ sở dữ liệu Oracle cho từng service

Lưu ý chung về kiểu dữ liệu:
- Khóa chính: `NUMBER(19,0)` (long) hoặc `NUMBER(10,0)` (int). Dùng sequence với identity column (Oracle 12c+).
- Boolean: `NUMBER(1,0)` (0/1), kết hợp value converter trong EF Core.
- Chuỗi: `NVARCHAR2(length)` hoặc `VARCHAR2(length CHAR)` nếu cần Unicode. Với text lớn dùng `CLOB`.
- JSON: `JSON` (Oracle 21c+) hoặc `VARCHAR2(4000)` có ràng buộc `IS JSON`, hoặc `CLOB` check `IS JSON` nếu dữ liệu lớn.
- Ngày giờ: `TIMESTAMP` (có mili giây) hoặc `TIMESTAMP WITH TIME ZONE` nếu cần múi giờ.
- GUID: `RAW(16)` (hiệu năng tốt hơn) hoặc `CHAR(36)`.

### 3.1. IdentityService
- **Oracle user/schema**: `IDENTITY_SERVICE`
- **Tablespace**: `TBS_IDENTITY`
- **Bảng chính**:
  - `AspNetUsers` (mở rộng từ IdentityUser):
    - `Id` RAW(16) PRIMARY KEY (dùng GUID)
    - `UserName`, `NormalizedUserName`, `Email`, `NormalizedEmail`, `PasswordHash`, `SecurityStamp`, `ConcurrencyStamp`, `PhoneNumber`, ...
  - `AspNetRoles`, `AspNetUserRoles`, `AspNetRoleClaims`, `AspNetUserClaims`, `AspNetUserLogins`, `AspNetUserTokens` (theo schema Identity mặc định, chuyển sang Oracle)
  - `UserProfiles`:
    - `UserId` RAW(16) REFERENCES AspNetUsers(Id)
    - `FullName` NVARCHAR2(200)
    - `PhoneNumber` NVARCHAR2(20)
    - `Address` NVARCHAR2(500)
    - `Country` NVARCHAR2(100)
    - `DateOfBirth` DATE
  - `RefreshTokens`:
    - `Id` NUMBER(19,0) GENERATED BY DEFAULT AS IDENTITY
    - `UserId` RAW(16) REFERENCES AspNetUsers(Id)
    - `Token` NVARCHAR2(500)
    - `ExpiresAt` TIMESTAMP
    - `CreatedAt` TIMESTAMP
    - `RevokedAt` TIMESTAMP (nullable)

### 3.2. HotelService
- **Oracle user/schema**: `HOTEL_SERVICE`
- **Tablespace**: `TBS_HOTEL`
- **Bảng chính**:
  - `Hotels`:
    - `Id` NUMBER(10,0) GENERATED BY DEFAULT AS IDENTITY
    - `Name` NVARCHAR2(200)
    - `Description` CLOB
    - `Address` NVARCHAR2(500)
    - `StarRating` NUMBER(1,0)
    - `City` NVARCHAR2(100), `Country` NVARCHAR2(100)
    - `Amenities` JSON (hoặc CLOB CHECK (Amenities IS JSON))
    - `ImageUrls` JSON
  - `Rooms`:
    - `Id` NUMBER(10,0) GENERATED BY DEFAULT AS IDENTITY
    - `HotelId` NUMBER(10,0) REFERENCES Hotels(Id)
    - `RoomType` NVARCHAR2(50)
    - `BedType` NVARCHAR2(50)
    - `MaxGuests` NUMBER(2,0)
    - `PricePerNight` NUMBER(10,2)
    - `Currency` NVARCHAR2(3)
  - `RoomAvailability`:
    - `RoomId` NUMBER(10,0) REFERENCES Rooms(Id)
    - `Date` DATE
    - `Status` NVARCHAR2(20) CHECK (Status IN ('Available','Reserved','Blocked'))
    - `PriceOverride` NUMBER(10,2)
    - `ReservedByBookingId` NUMBER(19,0) (nullable, logic tham chiếu sang BookingService)
    - PRIMARY KEY (RoomId, Date)
  - `Amenities`:
    - `Id` NUMBER(10,0) GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
    - `Name` NVARCHAR2(100)
    - `Icon` NVARCHAR2(200)
  - `RoomAmenities`:
    - `RoomId` NUMBER(10,0) REFERENCES Rooms(Id)
    - `AmenityId` NUMBER(10,0) REFERENCES Amenities(Id)
    - PRIMARY KEY (RoomId, AmenityId)
  - `RoomImages`:
    - `Id` NUMBER(10,0) GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
    - `RoomId` NUMBER(10,0) REFERENCES Rooms(Id)
    - `ImageUrl` NVARCHAR2(500)
    - `IsPrimary` NUMBER(1,0) DEFAULT 0

### 3.3. BookingService
- **Oracle user/schema**: `BOOKING_SERVICE`
- **Tablespace**: `TBS_BOOKING`
- **Bảng chính**:
  - `Bookings`:
    - `Id` NUMBER(19,0) GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
    - `UserId` RAW(16) (tham chiếu user từ IdentityService – không dùng FK vì cross-service, chỉ lưu ID)
    - `HotelId` NUMBER(10,0)
    - `RoomId` NUMBER(10,0)
    - `CheckInDate` DATE
    - `CheckOutDate` DATE
    - `NumberOfGuests` NUMBER(2,0)
    - `Status` NVARCHAR2(20) CHECK (Status IN ('Pending','Confirmed','Cancelled','Completed'))
    - `TotalAmount` NUMBER(12,2)
    - `Currency` NVARCHAR2(3)
    - `CreatedAt` TIMESTAMP
  - `BookingGuests`:
    - `Id` NUMBER(19,0) GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
    - `BookingId` NUMBER(19,0) REFERENCES Bookings(Id)
    - `FullName` NVARCHAR2(200)
    - `Age` NUMBER(3,0)
    - `IsMainGuest` NUMBER(1,0)
  - `BookingStatusHistory`:
    - `Id` NUMBER(19,0) GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
    - `BookingId` NUMBER(19,0) REFERENCES Bookings(Id)
    - `Status` NVARCHAR2(20)
    - `ChangedAt` TIMESTAMP
    - `ChangedBy` NVARCHAR2(200)
  - `OutboxMessages` (Transactional Outbox):
    - `Id` NUMBER(19,0) GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
    - `EventType` NVARCHAR2(200)
    - `EventData` CLOB (lưu JSON của event)
    - `CreatedAt` TIMESTAMP
    - `ProcessedAt` TIMESTAMP (nullable)
    - `Error` NVARCHAR2(4000) (nullable)

### 3.4. PaymentService
- **Oracle user/schema**: `PAYMENT_SERVICE`
- **Tablespace**: `TBS_PAYMENT`
- **Bảng chính**:
  - `Payments`:
    - `Id` NUMBER(19,0) GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
    - `BookingId` NUMBER(19,0)
    - `UserId` RAW(16)
    - `Amount` NUMBER(12,2)
    - `Currency` NVARCHAR2(3)
    - `PaymentMethod` NVARCHAR2(50)
    - `TransactionId` NVARCHAR2(200)
    - `Status` NVARCHAR2(20) CHECK (Status IN ('Pending','Completed','Failed','Refunded'))
    - `CreatedAt` TIMESTAMP
  - `Invoices`:
    - `Id` NUMBER(19,0) GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
    - `BookingId` NUMBER(19,0)
    - `InvoiceNumber` NVARCHAR2(100)
    - `IssuedDate` TIMESTAMP
    - `TotalAmount` NUMBER(12,2)
    - `TaxAmount` NUMBER(12,2)

### 3.5. NotificationService
- **Oracle user/schema**: `NOTIFICATION_SERVICE`
- **Tablespace**: `TBS_NOTIFICATION`
- **Bảng chính**:
  - `Notifications`:
    - `Id` NUMBER(19,0) GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
    - `UserId` RAW(16)
    - `BookingId` NUMBER(19,0)
    - `Type` NVARCHAR2(20) CHECK (Type IN ('Email','SMS'))
    - `Subject` NVARCHAR2(500)
    - `Body` CLOB
    - `Status` NVARCHAR2(20) CHECK (Status IN ('Pending','Sent','Failed'))
    - `CreatedAt` TIMESTAMP
    - `SentAt` TIMESTAMP (nullable)
  - `NotificationTemplates`:
    - `Id` NUMBER(10,0) GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
    - `TemplateKey` NVARCHAR2(100) UNIQUE
    - `SubjectTemplate` NVARCHAR2(500)
    - `BodyTemplate` CLOB
